# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| Environment is recorded | `repro_report_markdown`'s stated Environment line, read against any version details named inline in `issue.body_markdown` | Pass if the report states concrete versions actually used. If the issue also names environment details, they must match or the mismatch must be explicitly acknowledged. If the issue names no environment details, a concrete environment statement in the report is sufficient on its own. Fail only if the report's environment section is missing entirely, or contradicts what the issue names with no acknowledgment. | required |
| Steps are complete and followable | `repro_report_markdown`'s steps/transcript section | Pass if it names a concrete starting state and each command a stranger could run verbatim. Fail if a step assumes unstated setup, or the section just restates the issue's own steps without an independent walkthrough. Unclear if no steps/transcript section exists. | required |
| Behavior shown matches the issue | The output/transcript inside `repro_report_markdown`, read against the specific symptom in `issue.body_markdown` | Pass if the transcript shows the same symptom named in the issue, OR — for an honest cannot-reproduce outcome — the transcript shows a specific, concrete attempt to trigger that exact symptom with the actual result recorded (not just "it didn't happen," but what was actually observed instead). Fail if the transcript shows an unrelated error, a setup failure with no real attempt at the reported symptom, or no transcript is included at all. Unclear if the issue names no concrete, checkable symptom. | required |
| Outcome is stated honestly | `repro_report_markdown`'s stated Expected vs. Actual (or explicit conclusion), read against its own transcript | Pass if the stated outcome matches what the transcript shows — an honest, evidenced "could not reproduce" is a full pass. Fail if it claims reproduction the transcript doesn't support, or claims success with no transcript at all. | required |
| Words respect the repo's conventions | `claim_comment_markdown` and `repro_report_markdown`, read against `repo_facts.raw_markdown`'s "bug reports: template asks for" line and "contribution policy" line | Fail only if the contribution policy contains explicit disclosure language (e.g., "must be disclosed," "must state the tool used," "disclose AI assistance") — a real requirement to name AI usage or its extent in the comment — AND the comment includes no such disclosure. Do NOT fail for policies that merely welcome AI use, ask contributors to review/understand AI-generated content, ask contributors to explain their changes, or warn that low-quality AI content will be rejected — none of those require disclosure in the comment itself. Fail if the comment itself states or implies it was AI-generated in a repo whose policy requires human-authored comments. Also fail if the comments skip a field the bug-report template explicitly asks for. | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails or is unclear (unclear counts as fail). Preferred checks never change the verdict.
